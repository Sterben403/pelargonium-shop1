# ADR-002: релиз при каждом слиянии и DORA по GitHub Deployments

- Статус: принято
- Дата: 18.11.2026
- Автор: Мурзаканов Еснур
- Участник согласования: Мурат Аяулым

## Контекст

В лабораторной работе № 10 DORA считалась по одному ручному выпуску MVP в Тильде. Lead time 49 дней
получился как длительность всего проекта, а не время одного изменения: изменения копились неделями,
коммиты делались пакетами, задачи закрывались задним числом. По такой истории нельзя понять,
какое изменение что сломало и кто за него отвечал. Код сайта в репозитории не хранился.

## Драйверы решения

- каждое изменение должно быть видно в истории сразу, с автором, ревьюером и временем выпуска;
- метрики должны считаться из системы автоматически, без ручных записей;
- выпуск должен быть обратимым;
- без платных сервисов и без отдельного хостинга.

## Рассмотренные варианты

### Вариант 1. Оставить ручной журнал выпусков

Плюсы: ничего не менять. Минусы: данные вносятся задним числом, lead time не отражает изменения,
сбои легко не записать.

### Вариант 2. Выпуск на внешний хостинг (Render, Neon)

Плюсы: живой сайт в интернете. Минусы: новые аккаунты и сервисы, ограничения бесплатных тарифов;
для расчёта метрик не обязателен.

### Вариант 3. Релиз при каждом слиянии в main средствами GitHub

Плюсы: всё внутри GitHub и бесплатно; каждое слияние автоматически даёт образ, GitHub Release
и запись Deployment со статусом; метрики считаются из API.
Минусы: «продакшен» — это выпущенный и проверенный образ, а не постоянно работающий сайт.

## Решение

Выбран вариант 3. Каждое слияние PR в `main` выпускается в окружение `production`
(образ в GitHub Packages, GitHub Release, GitHub Deployment). DORA считается только по Deployments,
ручной журнал удалён. Работа ведётся маленькими PR: одна задача — одна ветка — один PR.

## Последствия

- lead time считается для каждого изменения от его первого коммита до выпуска;
- неудачный выпуск автоматически попадает в долю неудачных изменений, следующий успешный — во время восстановления;
- если понадобится живой сайт, к пайплайну добавляется шаг развёртывания образа на сервер — расчёт метрик не меняется.
