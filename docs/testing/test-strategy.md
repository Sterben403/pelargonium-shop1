# Стратегия тестирования Pelargonium Shop

## Цель

Качество проверяется **до** выпуска и на каждом изменении: каждый PR проходит одни и те же проверки,
и в `main` не попадает ничего, что их не прошло (Ruleset). Тестировщики не «добавляют качество в конце» —
проверки встроены в процесс.

## Уровни тестирования (пирамида)

| Уровень | Что проверяет | Инструмент | Где запускается | Сколько |
| --- | --- | --- | --- | --- |
| Модульные и API | логика заказа и наличия, фильтры каталога, вход владелицы, вебхук Тильды, загрузка фото, проверка настроек | pytest + TestClient на PostgreSQL | CI, каждый PR | 24 |
| Тесты репозитория | обязательные документы, релизный план, этапы пайплайна, расчёт DORA | pytest | CI, каждый PR | 10 |
| Живой тест сервиса (smoke) | 33 проверки на запущенном образе: каталог, заказ, вебхук Тильды, кабинет, фото | `backend/scripts/smoke_test.py` | CI, каждый PR | 1 сценарий |
| Сквозные (E2E) | путь покупателя в настоящем браузере: фильтр, корзина, ошибки формы, маска телефона, заказ; язык KZ; кабинет владелицы | Playwright | CI, каждый PR | 3 |
| Нагрузочные | профиль покупателей: каталог, карточки, health | Locust | после каждого слияния в `main` и вручную | 1 профиль |
| Безопасность | секреты в истории, уязвимые зависимости и образ | gitleaks, Trivy | CI, каждый PR | — |
| Ручные | приёмка заказчиком (UAT), внешний вид в Тильде | сценарии UAT | перед вехой | 8 сценариев |

Больше всего быстрых тестов внизу, меньше всего медленных E2E наверху. Перевёрнутой пирамиды нет:
E2E проверяют только сквозные пути, всё остальное — на уровне API.

## Автоматизация и регресс

- Все автоматические проверки — обязательные статусы в Ruleset для `main`.
- Полный прогон на PR занимает около 2,5 минут.
- Нестабильный тест не отключают: его чинят или удаляют. Пример — гонка при старте сервера
  (см. [postmortem](../ops/postmortem-2026-11-18-startup-race.md)): причина найдена и исправлена,
  проверку не просто перезапускали.

## Тестовые данные

- Каталог — 15 учебных сортов из `backend/app/seed_data.json`. Фото — Wikimedia Commons, без персональных данных.
- Заказы в тестах — **выдуманные**: имена «Smoke Test», «E2E Покупатель», телефоны `+7 701 000 00 00` и т. п.
- **Копия рабочей базы на тестовый стенд не переносится.** Если для разбора проблемы нужны реальные заказы,
  данные обезличиваются заменой значений, а не удалением фамилий:

  ```sql
  UPDATE orders SET
    customer_name = 'Покупатель ' || id,
    phone = '+7700' || lpad(id::text, 7, '0'),
    address = CASE WHEN address <> '' THEN 'Адрес ' || id ELSE '' END,
    comment = '';
  ```

- Автотесты работают на отдельной базе `pelargonium_test`, она пересоздаётся перед каждым тестом.

## Среды

| Среда | Что это | Данные |
| --- | --- | --- |
| Локальная | `docker compose up -d` + `uvicorn` | учебный каталог |
| CI | PostgreSQL в контейнере, образ запускается с `APP_ENV=production` | пустая база + каталог |
| Production | выпущенный образ из GitHub Packages | рабочие заказы |

## Нефункциональные требования

| Что | Чем | Цель | Результат |
| --- | --- | --- | --- |
| Нагрузка | Locust, 50 пользователей, 60 с | p95 < 800 мс, 0% ошибок | p95 19 мс, 0 ошибок из 1477 запросов (18.11.2026, локально) |
| Отказ базы | остановка PostgreSQL | `/api/health` → 503, сервис не падает; при старте ждёт базу до 30 с | проверено тестами `test_startup.py` |
| Безопасность | gitleaks, Trivy | нет секретов и уязвимостей HIGH/CRITICAL с исправлением | проходит |
| Мультиязычность | E2E + ручная проверка | RU / KZ / EN, длинные казахские строки не ломают вёрстку | E2E проверяет KZ |
| Мобильная вёрстка | ручная проверка 375 px | нет горизонтальной прокрутки | проверено вручную |

Нагрузочный тест на CI-стенде даёт только относительное сравнение между версиями: стенд не равен продакшену.

## Мониторинг демо-стенда

Uptime Kuma поднимается вместе с базой (`docker compose up -d`) → http://localhost:3001.
Монитор: тип HTTP(s), адрес `http://host.docker.internal:8010/api/health`, интервал 60 с,
ожидаемый ответ — код 200. Если база недоступна, health возвращает 503 и монитор краснеет.

## Инструменты

Всё открытое и бесплатное: pytest, Playwright, Locust, ruff, gitleaks, Trivy, Uptime Kuma, GitHub Actions.
Для ручных запросов к API используется Swagger UI сервиса (`/docs`).
