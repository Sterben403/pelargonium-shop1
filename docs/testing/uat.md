# Приёмочное тестирование (UAT)

## Правила

| Вопрос | Решение |
| --- | --- |
| Что принимаем | инкремент: каталог, оформление заказа, кабинет владелицы, виджет для Тильды |
| Кто тестирует | другая команда в роли заказчика: один участник — «покупатель», второй — «владелица магазина» |
| Кто проводит | Мурат Аяулым (PM) — ведёт протокол; Мурзаканов Еснур — стенд и ответы на вопросы |
| Стенд | `docker compose up -d` + сервер, страница `http://localhost:8010/demo`, кабинет `/admin`; данные — учебный каталог из 15 сортов, без реальных покупателей |
| Длительность | 45 минут; 10 минут — короткое обучение (как открыть каталог и кабинет, куда записывать замечания) |
| Замечания | в трекер GitHub Issues, шаблон «Замечание UAT» — сразу с типом и приоритетом |
| Результат | подписанный протокол ниже, а не список идей |

UAT — это не поиск ошибок и не демонстрация: работает заказчик, по заранее согласованным сценариям.
Сценарии согласуются с проверяющей командой **до** начала.

## Сценарии

Сценарии написаны на языке работы пользователя. Сценарий пройден, если выполнен критерий прохождения.

| № | Сценарий | Шаги | Ожидаемый результат | Критерий прохождения |
| --- | --- | --- | --- | --- |
| UAT-01 | Покупатель-новичок выбирает розовидный сорт без названия, только по внешнему виду | открыть каталог → фильтр «Розобудная» → открыть карточку | видны фото, цена, наличие, описание и памятка по уходу | нужный сорт найден меньше чем за 1 минуту, без регистрации |
| UAT-02 | Покупатель заказывает 2 растения с самовывозом | добавить в корзину → количество 2 → оформить → имя и телефон → отправить | показан номер заказа PS-…, корзина очищена | номер получен, сумма = цена × 2 |
| UAT-03 | Покупатель ошибся в телефоне | ввести телефон из 5 цифр и отправить | заявка не отправлена, у поля подсказка; после исправления подсказка пропадает | ни одной лишней заявки в кабинете |
| UAT-04 | Покупатель выбирает курьера | выбрать «Курьер» → отправить без адреса → указать адрес → отправить | без адреса заявка не уходит; с адресом приходит номер | адрес виден у заказа в кабинете |
| UAT-05 | Покупатель пытается купить сорт, которого нет | найти сорт с пометкой «Нет в наличии» | кнопка «В корзину» недоступна | заказать недоступный сорт невозможно |
| UAT-06 | Казахоязычный покупатель оформляет заказ | переключить язык на KZ → пройти UAT-02 | весь путь на казахском, тексты не обрезаны | заказ оформлен, не встретилось русского текста |
| UAT-07 | Владелица обрабатывает новый заказ | войти в кабинет → найти заказ → позвонить по ссылке → статус «Подтверждён» → «Выполнен» | заказ виден с контактами и составом; статусы меняются | заказ из UAT-02 найден и доведён до «Выполнен» |
| UAT-08 | Владелица обновляет каталог без разработчика | изменить цену и наличие сорта → добавить новый сорт с фото с телефона → проверить на сайте | изменения сразу видны покупателю | новый сорт с фото виден в каталоге, наличие 0 показывает «Нет в наличии» |

## Разбор замечаний

Каждое замечание при заказчике относится к одной из трёх групп:

| Тип | Что это | Что делаем |
| --- | --- | --- |
| Дефект | расхождение с согласованным критерием | исправляем в рамках работ, по приоритету |
| Уточнение требования | критерий понят по-разному | согласуем формулировку, обновляем критерий |
| Запрос на изменение | новая функция | оцениваем срок и что уходит взамен — «да, и вот что это меняет» |

| Приоритет | Что это | Исправление |
| --- | --- | --- |
| P1 | заказ не оформляется, данные теряются или искажаются | в тот же день |
| P2 | ключевой сценарий не работает, но есть обход | 2 рабочих дня |
| P3 | неудобство, обход есть | ближайший релиз |
| P4 | косметика | без обязательств |

Severity (насколько сломано технически) ставит команда, приоритет (насколько срочно для бизнеса) — заказчик и PM.
